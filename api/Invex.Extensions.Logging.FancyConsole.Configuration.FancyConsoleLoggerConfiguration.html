Configuration options for the fancy console logger. Bound from the Logging:FancyConsole configuration section when registered via AddFancyConsole(ILoggingBuilder), and can also be set programmatically via the AddFancyConsole(ILoggingBuilder, Action<FancyConsoleLoggerConfiguration>) overload.

public sealed class FancyConsoleLoggerConfiguration
Inheritance
object
FancyConsoleLoggerConfiguration

Remarks

Changes from configuration sources that support reload (for example, appsettings.json loaded with reloadOnChange) are applied to subsequent log entries. Programmatic configuration delegates are reapplied when options are rebuilt, so their values continue to override bound configuration. Messages, categories, and scopes are written as literal text, not Spectre.Console markup.

IncludeScopes

Gets or sets whether active logging scopes are shown after the category, separated by => , in the Standard and SingleLine layouts. Detailed always shows scopes and Minimal never does. Defaults to DefaultIncludeScopes (false).

public bool IncludeScopes { get; set; }

Property Value

bool

Remarks

Message-template scopes (for example, logger.BeginScope("Order {OrderId}", 42)) are shown as their formatted text. Other key/value scopes are shown as comma-separated Key=Value pairs, and any other scope object is shown using object.ToString(). Scopes are shown outermost first. Null and empty scope text is skipped; whitespace and line breaks are preserved.

LevelStyles

Gets or sets per-Microsoft.Extensions.Logging.LogLevel Spectre.Console style strings (for example, "bold red", "#ff8800", or "black on yellow") used for each entry's level-colored text. A mapped null or whitespace value disables styling for that level. Missing levels and values that are not valid styles use the built-in defaults: grey (Trace), seagreen3 (Debug), skyblue1 (Information), gold1 (Warning), darkorange (Error), and fuchsia (Critical). Empty by default.

public Dictionary<LogLevel, string?> LevelStyles { get; set; }

Property Value

Dictionary<LogLevel, string>

Remarks

Styles apply to headers, level codes, and Detailed field labels. Message text remains unstyled, and exception text uses ExceptionTextStyle or the Pretty formatter's own styles.

LogToStandardErrorThreshold

Gets or sets the minimum level written to standard error instead of standard output. Defaults to DefaultLogToStandardErrorThreshold (Microsoft.Extensions.Logging.LogLevel.None), which writes every entry to standard output.

public LogLevel LogToStandardErrorThreshold { get; set; }

Property Value

LogLevel

Remarks

The entire entry, including scopes and exception output, is sent to the selected stream. Routing uses the entry's level, not whether it carries an exception, and does not filter entries.

TimestampFormat

Gets or sets a .NET date and time format string for entry timestamps, formatted with the invariant culture. When null or empty (the default), the layout's default is used: HH:mm:ss.fff for Standard and SingleLine, and yyyy-MM-dd HH:mm:ss.fff zzz for Detailed. The Standard header line always shows the date and UTC offset. Ignored by Minimal.

public string? TimestampFormat { get; set; }

Property Value

string

Remarks

A format that raises System.FormatException falls back to the layout's default. Formatting controls the displayed timestamp only; it does not change when entries are captured.

UseColors

Gets or sets whether level and exception styles are applied. When false, all output is written without styling, including Pretty exceptions. Defaults to DefaultUseColors (true).

public bool UseColors { get; set; }

Property Value

bool

Remarks

Even when enabled, colors are only emitted if the console supports them. Spectre.Console detects terminal capabilities and honors the NO_COLOR environment variable.

UseShortCategoryName

Gets or sets whether categories are shortened to the text after their last . outside generic arguments (for example, MyApp.Services.OrderService becomes OrderService). Defaults to DefaultUseShortCategoryName (false).

public bool UseShortCategoryName { get; set; }

Property Value

bool

Remarks

Dots inside generic arguments are ignored: MyApp.Repository<MyApp.Models.Order> becomes Repository<MyApp.Models.Order>. Categories with no qualifying dot or a trailing dot are unchanged. Shortening affects display only; framework category filters still use the original category.
